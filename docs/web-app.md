# library live · 会员端 Web App 与后台（Demo v2）

> 先做 Web App，再做小程序。会员端可以从浏览器「添加到主屏幕」，全屏打开、有自己的图标和启动画面，不用过审核，改完即上线。后台和会员端共用一套业务规则，一边的操作另一边一秒内看到。

## 设计：同一座图书馆，两层读者

**L0 图书馆（非会员、游客）**：阅览室。目录卡片、橡皮图章、今晚的节目单（playbill）、墨线画在纸上的平面图。会员预留的两张圆卡座（B05 1957、B06 1976）盖着火漆，19:00 一到火漆在屏幕上裂开、向所有人开放。夜里是深绿色的阅览室，白天是纸色。

**L1+ 机器层（会员）**：图书馆下面的机器。
- 夜里是 CRT 荧光屏：扫描线、轻微闪烁、荧光拖影；荧光颜色可选琥珀 P3、绿 P1、冰蓝 P4。
- 白天是针式打印机的绿条打孔纸（green-bar），两侧带链轮孔；可选绿条、蓝条、素纸。
- 首页是一个终端：`whoami`、`mode`、今晚各分区的余量用字符进度条 `[######----]` 画出来，`ls -la /hidden` 列出隐藏层。
- 会员卡是一张 IBM 029 打孔卡，每一列按 Hollerith 编码打孔，内容就是会员编号和姓名；背面有一行隐形墨水，23:00 以后才显影。会员码 6 位数字，每 30 秒更新。
- 订座页的平面图整张由 ASCII 字符组成，点字符区域就是选分区；白天切换成日间布局。
- 入会（付费或领取邀请）的那一刻播放一段字符解密动画：噪点逐列落定成 ACCESS GRANTED，不到 3 秒，可以点掉（R-LAY-05）。
- 彩蛋：首页的大字标题连点五下转出一个 ASCII 甜甜圈（Andy Sloane 的 donut.c，2006）；在字符平面图的左上角按住不放，会找到一间地图上没画的房间（L3）。

**参考**：终端皮肤的做法参考了 GitHub 上星数靠前的终端 UI 项目：charmbracelet/bubbletea、Textualize/textual（TUI 面板与边框）、ghostty-org/ghostty、Swordfish90/cool-retro-term（CRT 荧光与扫描线）、webtui/webtui（网页上的终端组件）、magiblot/tvision（Turbo Vision 的 F 键菜单）。FIGlet 大字是用 pyfiglet 的 small 字体预先生成的纯 ASCII。所有效果都是 CSS 与几十行 JS，没有引入任何库。

**后台**：借还台。绿色台呢侧栏、黄铜、目录卡片、红色图章；订单状态借用投资的说法：待门店确认是「尽调中」，确认是「已交割」，婉拒是「本轮未进」。只有操作日志用了机器层的样子：一卷绿条打印纸。

## 会员端（`/app/`）

| 身份 | 能看到、能做什么 |
| --- | --- |
| 游客 | 图书馆首页、今晚节目单、平面图（可看不可订）、公开活动、入会申请、登录 |
| 非会员 | 订未来 3 天：卡座交订金（非会员低消的 30%），散座买门票（每人每场最多 4 张）；看到会员活动的标题和一句话；申请入会 |
| 申请中 / 待补资料 / 已通过 | 「我的」里是申请进度；待补资料可以改了再交；通过后付首月会员费（模拟支付）立即生效 |
| 受邀人 | 打开邀请链接看到火漆信封，拆开即领取 3 个月会员 |
| 会员 | 机器层全部内容：订未来 7 天，会员低消、会员散座免票、预留卡座；白天签到（扫门口的日戳签到码、填同行人数）、开放座谈、会议申请；L1 内容（The Memo、会员时间、隐藏酒单）和按条件解锁的 L2 / L3 |
| 已到期 | 回到图书馆皮肤；30 天内可以直接续费（不需要重新审核） |

订座流程：选日期 → 点分区（地图或列表）→ 看分区卡片（会员价与非会员价并排）→ 人数、加桌、备注 → 报价 → 模拟支付（10 分钟锁定）→ 订单页。卡座、多桌、带备注的订单进入「尽调中」，订单页显示 30 分钟倒计时；散座即时成功。门店婉拒时，订单页显示原因、建议和「改订这个区域」。

## 与执行规格的差异（冲突登记）

执行规格说「与人类同事版冲突时以执行规格为准，并登记」。这一版按 v0.3 文末的新规则做，和执行规格不一致的地方如下，需要在规格第 15 节补登记、和老板确认：

| # | 执行规格 | 这一版 | 理由 |
| --- | --- | --- | --- |
| 1 | DEC-01 / R-BK-01：在店内图上精确选桌，确认后桌号不变 | 按分区订座；订单记录分区，系统在区内预留具体的桌（保证不超卖，INV-01），桌号在确认后才展示给客人 | 新规则「选桌上，不要选特定桌，按照分区就可以」 |
| 2 | R-BK-02 / Q-01：门店不能改桌，只能确认或拒绝 | 门店确认时可以在**同一分区内**换桌（`admin.booking.confirm` 的 `codes`）；不能换到别的分区 | 按分区订座的必然结果。同一分区的卡座同一价档，换桌不改变客人付过的订金和低消（PRD 5.x：确认分配不得擅自增加用户已同意的低消） |
| 3 | 店内图点桌显示桌位卡片（9.3） | 分区卡片（名称、标签、余量、会员价与非会员价）；桌位卡片的内容（年份、故事）保留在平面图和后台排桌里 | 同上 |
| 4 | — | 吧台 8 座拆成两段（S01、S02 各 4 座） | 规格里「多资源 → 人工确认」；拆段后 1–4 人的吧台订单仍是即时成功 |
| 5 | 每场会员预留卡座 2 张，桌号未定 | 选了舞台前的两张圆卡座 B05、B06 | 平面图上离舞台最近；后台可按场次修改 |

其余已定事项按规格实现：会员 7 天 / 非会员 3 天窗口（含当天）、21:30 停止线上订座、10 分钟支付锁定、卡座 / 多桌 / 备注 30 分钟人工确认、超时关闭并全额退款、订金 = 下单身份低消 × 30% 抵当晚消费、门票每人每场最多 4 张、会员跨到期日按非会员规则（R-BK-04）、19:00 释放会员预留、白天签到码与同行人数、会员按自然月对日到期与 30 天内免审续费、赠送 3 个月、L2/L3 不对看不见的人返回内容（INV-11）。

`npm test` 跑 38 个验收用例（编号对应执行规格第 13 节，如 `A01`–`A19`、`B01`–`B11`、`C02`–`C13`）。

## 给老板演示（十分钟）

电脑开后台（工作台），手机开会员端。后台「规则与设置」最下面、会员端「我的」最下面都有演示时钟，会员端还有身份切换，两边同步。演示时钟只往前走：点一个时间，会跳到下一个这样的时刻（需要时是第二天）；「现在」回到真实时间。

1. **图书馆**：手机先不登录，看图书馆首页、今晚的节目单、平面图上盖着火漆的两张圆卡座。
2. **19:00**：手机停在「预订」页。后台「规则与设置」里演示时钟点「18:58」，再点「19:02 入夜」→ 手机上火漆裂开，B05、B06 向所有人开放，页面从白天的纸色换成夜里的深绿；后台工作台从日间切到夜间。
3. **非会员订卡座**：身份切到「非会员」，订今晚的墙边卡座 5 人 → 付订金（模拟）→ 订单页「尽调中」和 30 分钟倒计时。
4. **门店确认**：后台工作台里出现这笔订单 → 「确认 · 排桌」，把系统预留的桌换成区内另一张空桌 → 交割。手机上订单变成「已交割」，并显示桌号和它的年份（如 B04「1984」）。（也可以演示「婉拒」：写原因、建议改订沙龙沙发，手机上出现改订按钮，订金 20 秒后退回。）
5. **入会，进入机器层**：身份切到「受邀人」，首页点「打开邀请函」，拆开信封 → 字符解密动画 → 整个 App 变成终端。看打孔卡会员卡、6 位会员码、字符平面图。
6. **门口核验**：后台「核验」，填入手机上的会员码 → 显示会员与今晚订单；再填订单凭证 → 入场，抵扣订金。
7. **白天**：演示时钟点「14:00 白天」→ 会员端变成绿条打孔纸；签到（读取门口的码、填同行人数）→ 解锁「借阅书单」（L2）；申请一个会议 → 后台「会员时间」里同意或提议调整。

## 运行与部署

```bash
npm start            # http://localhost:8080/app/  与  /admin/
npm run reset        # 恢复初始演示数据
npm test             # 验收用例
```

| 模式 | 什么时候 | 数据 |
| --- | --- | --- |
| 服务器模式 | `npm start`（或部署 `server/server.js`） | `server/data/db.json`，所有设备共享，实时同步（SSE） |
| 本地演示模式 | 纯静态托管、`file://`，或地址后加 `?mode=local` | 每台设备的浏览器里各一份；同一浏览器的多个标签页互相同步 |
| 离线 | 这台设备上次连的是服务器，现在没网 | 显示上次缓存的内容 |

环境变量：`PORT`（默认 8080）、`HOST`（默认 0.0.0.0）、`SV_DATA_DIR`（数据目录）。服务器每 10 秒扫一次到期事项（支付锁定 T5、确认超时 T10、散场未到店 T14、退款到账），本地模式在浏览器里做同样的事；19:00 的释放由桌位状态按时间直接算出。

**关于 HTTPS**：Service Worker（离线缓存）和安卓的「安装」只在 HTTPS 或 `localhost` 下可用。给老板长期试用，建议部署到带 HTTPS 的国内云服务器（需 ICP 备案），反向代理到 Node；SSE 接口 `/api/stream` 需要关闭代理缓冲（nginx `proxy_buffering off`）。

## 添加到主屏幕

- **iPhone**：Safari 打开 → 「分享」→「添加到主屏幕」。
- **安卓**：Chrome 或系统浏览器菜单 →「添加到主屏幕 / 安装应用」。
- **微信里打开的**：微信内置浏览器不能直接添加到桌面，先点右上角「···」→「在浏览器打开」。

## 架构

```
app/ (会员端)  ─┐
                ├─ shared/api.js ── 服务器模式：POST /api/<method>，GET /api/stream（SSE）
admin/ (后台) ──┘                └─ 本地模式：直接在浏览器里运行 shared/core.js
                                       │
server/server.js ── shared/core.js ────┘   （同一份业务规则）
                    shared/plan.js         （平面图：一份几何，两种画法）
```

- `shared/core.js`：数据模型、演示数据、权限（public / user / staff / 店长）、订单状态机、到期扫描和全部 80 多个接口。服务器和浏览器跑同一份代码。
- `shared/plan.js`：按 2026-11-06 平面图量出的字符坐标（47 × 79 格），`planSVG` 画成纸上的墨线图（图书馆皮肤、后台座位图），`planASCII` 画成纯 ASCII（会员终端）。分区、桌号、容量、价档、年份故事都在这里。`shared/plan.css` 是两边共用的墨线样式。
- `app/ascii.js`：FIGlet 大字、解码文字、打字机、字符进度条、解密动画、打孔卡、甜甜圈。
- 前端没有框架：一个状态对象、`html``` 模板（插值默认转义）、事件委托。
- 演示时钟：`db.clock.offsetMs`，所有接口按「真实时间 + 偏移」计算，所以 19:00 可以随时发生。

主要数据：`users` · `memberships`（会籍分段：赠送 / 付费）· `applications` · `invites` · `sessions`（每晚一场）· `bookings` · `occupancies`（桌位占用：支付锁定 / 待确认 / 已确认 / 线下占桌）· `holds` · `payments` · `refunds` · `tickets` · `redemptions`（订金抵扣）· `events` / `registrations` · `content` / `unlocks`（L1–L3）· `checkins` · `meetings` · `shelf` · `notices` · `audit`。

## 和小程序的关系

先用 Web App 把流程、页面和设计跑通、给会员用起来；小程序以后作为另一个前端接入同一套接口。业务规则都在 `shared/core.js`，接口形状（`POST /api/<method>`）对小程序的 `wx.request` 同样适用，届时补微信登录和手机号授权即可。
