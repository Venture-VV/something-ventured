# library live · 会员端 Web App 与后台（MVP）

> 先做 Web App，再做小程序。会员端可以从浏览器「添加到主屏幕」，全屏打开、有自己的图标和启动画面，不用过审核，改完即上线。后台和会员端共用一套业务规则，一边的操作另一边一秒内看到。

## 这一版改了什么

产品经理看过上一版：界面一眼就是 AI 做的，不够人性化，很多界面和按键不符合用户习惯。这一版按「最小可用、清晰好用」重做，只保留三件事：

1. **订座**：按区域订，门店确认时安排具体桌号。
2. **白天座谈**：会员看日程、报名、取消报名。
3. **会员邀请**：门店发邀请链接，朋友打开就能领取会员。

先从界面上拿掉的：图书馆 / ASCII 两套皮肤、入会申请审核、白天签到、会议申请、隐藏内容分层与彩蛋、分享与播客活动、账目和操作日志页。这些功能的规则和数据仍在 `shared/core.js` 里，`npm test` 照常验证，以后需要时再接回界面。

## 界面原则

- **一套界面**：系统字体（苹方 / 微软雅黑），浅灰底、白卡片，品牌绿只用在主按钮和选中状态。
- **常见的导航**：底部三个标签「订座 · 座谈 · 我的」；二级页面左上角是返回，不显示标签栏。
- **一页一个主按钮**，固定在屏幕底部；金额在提交前写清楚。
- **用客人听得懂的话**：待支付、等待门店确认、预订成功、门店没能接受、订单已关闭。没有英文行话，没有暗语。
- **用到才登录**：不登录也能看区域、价格和座谈；点「预订」「报名」「领取」时才登录，登录后回到原来那一页。
- **演示用的东西收起来**：演示账号在登录页底部，演示工具在「我的」最下面的小字链接里，正式版去掉即可。

## 会员端（`/app/`）

| 页面 | 内容 |
| --- | --- |
| 订座 | 日期（会员 7 天、非会员 3 天）→ 当晚演出 → 区域列表：每个区域写清楚桌型、低消和订金（或门票）、还剩几桌 / 几座。「看平面图」打开店内平面图，点区域也能直接订 |
| 填写预订 | 人数（超过一桌的人数会自动加桌）、备注；下方实时算出要付多少、是否需要门店确认；底部「提交订单」 |
| 支付 | 底部弹出支付页，10 分钟内支付（演示环境不真实扣款，正式版接微信支付） |
| 订单详情 | 顶部一句话说明当前状态和倒计时；确认后显示入场凭证和桌号；门店没接受时写明原因、退款进度，以及门店建议的「改订 XX」按钮 |
| 座谈 | 按日期列出接下来一周的座谈：时间、话题、主持、已报人数；非会员能看到标题，报名仅限会员 |
| 座谈详情 | 时间、地点、主持、名额、介绍；底部「报名参加」，已报名时显示「取消报名」 |
| 我的 | 会员状态（会员号、有效期、剩余天数；到期的可续费；受邀人有「查看并领取」）、我的预订、我报名的座谈、添加到手机桌面、退出登录 |
| 会员邀请 | 打开邀请链接看到会员权益和截止日期；手机号登录、填写称呼后「领取会员」，成功后直接去订座或看座谈 |
| 登录 | 手机号 + 验证码（演示验证码 `2026`），没有账号的手机号自动注册 |

## 后台（`/admin/`）

| 页面 | 内容 |
| --- | --- |
| 订单 | 顶部输入入场凭证核验（会员码也可以）；「待确认」列表带倒计时，每笔订单可以「确认」（在客人选的区域里勾选具体桌号）或「拒绝」（选原因、可建议客人改订别的区域，订金原路退回）；按日期查看各区域余量和全部订单 |
| 座谈 | 接下来的座谈列表；新建 / 编辑（话题、时间、主持、名额、地点、介绍、发布或草稿）；报名名单里勾选到场 |
| 邀请 | 填「写给谁」和（可选）限定手机号，生成邀请链接并复制，微信里直接发；已发出的邀请和领取情况，可停用 |
| 演示 | 演示时钟（让 19:00、白天等时刻随时出现）和重置演示数据，正式版没有这一页 |

## 三条主流程（给老板演示）

电脑开后台，手机开会员端。

1. **订座**：手机「我的 → 演示工具」切到「非会员 陈一」→ 订座页选「墙边卡座」→ 人数 → 提交并支付订金 → 订单显示「等待门店确认」和倒计时。后台「订单」里出现这笔订单 → 确认，并换一张桌 → 手机上立刻变成「预订成功」，显示桌号和入场凭证。后台顶部输入凭证，核验入场。
   也可以演示拒绝：选原因、建议改订别的区域 → 手机显示原因、退款进度和「改订」按钮。
2. **邀请**：后台「邀请」→ 写「致 王先生」→ 生成链接 → 复制。用另一台手机（或无痕窗口）打开链接 → 手机号登录（验证码 `2026`）→ 填称呼 → 领取会员 → 成为会员。
3. **座谈**：后台「座谈 → 新建座谈」→ 发布。会员手机「座谈」里马上出现 → 报名。后台「报名名单」里能看到这位会员，勾选到场。

## 规则（沿用执行规格 v0.3）

- 预订窗口：会员 7 天、非会员 3 天（含当天）；当晚 21:30 后停止线上预订。
- 卡座：订金 = 下单身份低消 × 30%，抵当晚消费；门店 30 分钟内人工确认，超时自动关闭并全额退款。
- 散座、吧台：按人数预订；会员免门票，非会员每人每场最多 4 张门票；付款后立即确认（写了备注的需要门店确认）。
- 舞台前两张圆卡座每晚为会员预留，19:00 后空着的开放给所有人。
- 会员邀请：赠送 3 个自然月，从领取当天开始；到期后 1024 元 / 月主动续费，不自动扣款；到期 30 天内续费不重新审核。
- 白天 10:00–19:00 是会员时间，座谈仅会员可以报名，每人一个名额。
- 订单确认后的取消、待确认期间撤回、会员费退款：老板拍板前不开放（Q-10、Q-16、Q-13）。

## 和执行规格不一致、需要确认的地方

| 执行规格 | 这一版 | 理由 |
| --- | --- | --- |
| DEC-01 / R-BK-01：在店内图上精确选桌，确认后桌号不变 | 按区域订座；系统在区内先预留一张桌（保证不超卖），门店确认时可以在**同一区域内**换桌 | v0.3 新规则「不选特定桌，按分区」。同区同价档，换桌不改变客人付过的订金和低消 |
| R-BK-02：门店不能改桌，只能确认或拒绝 | 同上 | 同上 |
| — | 吧台 8 座拆成两段（各 4 座） | 1–4 人的吧台订单仍然即时确认 |

## 运行与部署

```bash
npm start            # http://localhost:8080/app/  与  /admin/
npm run reset        # 恢复初始演示数据
npm test             # 验收用例
```

| 模式 | 什么时候 | 数据 |
| --- | --- | --- |
| 服务器模式 | `npm start`（或部署 `server/server.js`） | `server/data/db.json`，所有设备共享，实时同步（SSE） |
| 本地演示模式 | 纯静态托管、`file://`，或地址后加 `?mode=local` | 每台设备的浏览器里各一份；同一浏览器的多个标签页互相同步 |

环境变量：`PORT`（默认 8080）、`HOST`（默认 0.0.0.0）、`SV_DATA_DIR`（数据目录）。服务器每 10 秒处理一次到期事项（支付超时、门店确认超时、退款到账）。

**关于 HTTPS**：离线缓存和安卓的「安装」只在 HTTPS 或 `localhost` 下可用。给老板长期试用，建议部署到带 HTTPS 的国内云服务器（需 ICP 备案），反向代理到 Node；实时推送接口 `/api/stream` 需要关闭代理缓冲（nginx `proxy_buffering off`）。

## 添加到手机桌面

- **iPhone**：Safari 打开 → 「分享」→「添加到主屏幕」。
- **安卓**：浏览器菜单 →「添加到主屏幕 / 安装应用」。
- **微信里打开的**：先点右上角「···」→「在浏览器打开」。

会员端「我的 → 添加到手机桌面」会按手机类型给出对应步骤。

## 架构

```
app/ (会员端)  ─┐
                ├─ shared/api.js ── 服务器模式：POST /api/<method>，GET /api/stream（SSE）
admin/ (后台) ──┘                └─ 本地模式：直接在浏览器里运行 shared/core.js
                                       │
server/server.js ── shared/core.js ────┘   （同一份业务规则）
```

- `shared/core.js`：数据模型、演示数据、权限、订单状态机、到期处理和全部接口。服务器和浏览器跑同一份代码。
- `shared/plan.js`：按 2026-11-06 平面图整理的区域、桌位、容量和价档；会员端的平面图由它画出（`shared/plan.css`）。
- 前端没有框架、没有构建步骤：一个状态对象、`html``` 模板（插值默认转义）、事件委托。字体用手机系统字体，不加载任何外部资源。

## 和小程序的关系

先用 Web App 把流程跑通、给会员用起来；小程序以后作为另一个前端接入同一套接口。业务规则都在 `shared/core.js`，接口形状（`POST /api/<method>`）对小程序的 `wx.request` 同样适用，届时补微信登录和手机号授权即可。
