# 会员端 Web App 与管理后台（Demo）

> 先做 Web App，再做小程序。会员端可以从浏览器「添加到主屏幕」，全屏打开、有自己的图标和启动画面，不用过审核，改完即上线；入场码离线也能用。

## 依据与待核对

这一版的功能与文案依据现有官网，也就是《Something Ventured 俱乐部介绍》（2026.10 内部同步版）：会员身份跨店跨城通用、3F Library 白天仅限会员 / 入夜对外开放、推荐 → 筛选 → 入会仪式 → 欢迎、每位会员有专属服务人员、闭门分享与播客录制等专享活动。

和老板对过的那份文档，这次没能读到（文档链接在本次会话里没有访问权限）。下面这些是 demo 里做的假设，请逐条对照：

- [ ] 会员端的五个入口：大堂、节目、钥匙、预订、我的
- [ ] 登录方式：手机号 + 短信验证码（demo 固定为 `2026`）；是否需要微信登录
- [ ] 入会流程的内部阶段：新申请 → 尽调中 → 入会仪式 → 已入会（另有「婉拒」）
- [ ] 会员推荐：会员生成邀请码，被推荐人凭码补全登记卡；每人同时在途推荐上限 5 位
- [ ] 预订：开业两周可订；白天为会员时段且仅限本人，夜晚每单最多 4 人；分区为长桌阅览 16 席、壁炉沙发 8 席、唱片角 6 席、小书房 2 间
- [ ] 节目：名额满了自动进候补，有人取消时候补按先后转正
- [ ] 藏书：开业前可预留，开业后到 3F 取书，借期 21 天，每人同时最多 3 本
- [ ] 携友规则（demo 公告里写的是：夜间每位会员可携两位来宾，白天不接待来宾）
- [ ] 2F Nightclub 与 1F Dining & Bar 显示为「规划中」，会员可按铃登记意向

演示数据里的会员、公司、申请人都是虚构的；书目是真实书名。

## 管理后台（`/admin/`）

| 页面 | 内容 |
| --- | --- |
| 员工通道 | 选人 + PIN（demo `1215`） |
| 总览 | 会员数、在途申请、距开业天数、开业周座位、待回复；新申请周柱状图、会员行业构成、开业周座位热力图（图 / 表切换，悬停与键盘聚焦都有数值）；楼层营业状态与昼夜模式切换（会员端楼层指南即时更新）；即将上映；实时动态 |
| 前台 | 黄铜铭牌上输入会员出示的 6 位入场码（可粘贴、自动提交）→ 盖章「Admitted · 欢迎光临」，自动把今天的预订标为已入座、把今晚节目标为已到场；今日预订、最近入场；演示用的「当前入场码」一键填入 |
| 入会申请 | 五个铜牌信格：新申请 / 尽调中 / 入会仪式 / 已入会 / 婉拒；卡片带行业色条、推荐人、停留天数；右侧抽屉是登记卡、押注、进度、内部备注，以及「开始尽调 → 安排入会仪式（选时间）→ 欢迎入会」。欢迎入会会自动发会员编号、分配专属服务人员，申请人的手机上立刻出现「领取你的钥匙」 |
| 会员 | 名册（搜索、按行业筛选）；档案抽屉里可更换专属服务人员、暂停 / 恢复，查看预订、节目、借书、推荐、到访 |
| 节目 | 新建 / 编辑（类型、时间、名额、海报颜色、仅限会员、草稿 / 发布 / 取消），带实时预览；报名名单与候补；取消节目会通知所有报名的人 |
| 预订 | 两周日期条、每个时段各区域的占用、当天预订列表（入座 / 未到 / 取消） |
| 藏书 | 在架 / 已预留 / 借出；借出（21 天）、归还、释放预留 |
| 礼宾 | 按铃请求收件箱，回复会推送到会员端 |
| 公告 | 写一封来信（右边实时预览成会员大堂里的样子），发给全部会员 |

后台和会员端是实时联动的：任何一边的操作，另一边一秒内刷新（服务器模式走 SSE，本地模式走同一浏览器的 storage 事件）。

## 给老板演示的五分钟

1. 电脑开后台（总览），手机开会员端，用「演示会员」进入。
2. 手机切到「钥匙」，后台切到「前台」，输入手机上的 6 位码 → 手机上当场盖章「欢迎光临」。
3. 手机「预订」里点平面图的壁炉沙发，订开业当晚 → 后台「预订」和总览热力图同步变化。
4. 另一台手机（或无痕窗口）用「演示申请人」进入 → 后台「入会申请」里把宋予安依次推进到入会仪式、欢迎入会 → 申请人手机上出现火漆邀请函，再出现「领取你的钥匙」。
5. 后台「公告」写一封信 → 会员大堂里立刻出现这封带火漆的来信。

## 运行与部署

| 模式 | 什么时候 | 数据 |
| --- | --- | --- |
| 服务器模式 | `npm start`（或部署 `server/server.js`） | `server/data/db.json`，所有设备共享，实时同步 |
| 本地演示模式 | 纯静态托管、`file://`，或地址后加 `?mode=local` | 每台设备的浏览器里各一份 |
| 离线 | 这台设备上次连的是服务器，现在没网 | 显示上次缓存的内容；钥匙页的入场码照常滚动 |

环境变量：`PORT`（默认 8080）、`HOST`（默认 0.0.0.0）、`SV_DATA_DIR`（数据目录）。

**关于 HTTPS**：Service Worker（离线缓存）和安卓的「安装」按钮只在 HTTPS 或 `localhost` 下可用。手机用局域网 IP（`http://192.168.x.x:8080/app/`）访问时，iPhone 仍然可以「添加到主屏幕」并全屏打开，但不会有离线缓存。给老板长期试用，建议部署到带 HTTPS 的国内云服务器（域名需要 ICP 备案），反向代理到 Node 即可；SSE 接口 `/api/stream` 需要关闭代理缓冲（nginx `proxy_buffering off`）。

## 添加到主屏幕

- **iPhone**：用 Safari 打开 → 底部「分享」→「添加到主屏幕」→「添加」。桌面图标是一枚酒店钥匙牌，名字叫 Ventured，打开时是红色启动画面。
- **安卓**：Chrome 或系统浏览器菜单 →「添加到主屏幕 / 安装应用」；支持的浏览器会直接弹出安装按钮（会员端「我的 → 添加到主屏幕」里有按钮）。
- **微信里打开的**：微信内置浏览器不能直接添加到桌面。会员端会识别微信，提示点右上角「···」→「在浏览器打开」，再按上面的步骤添加。

会员端「我的 → 添加到主屏幕」会按设备自动给出对应的步骤。

## 架构

```
app/ (会员端)  ─┐
                ├─ shared/api.js ── 服务器模式：POST /api/<method>，GET /api/stream（SSE）
admin/ (后台) ──┘                └─ 本地模式：直接在浏览器里运行 shared/core.js
                                       │
server/server.js ── shared/core.js ────┘   （同一份业务规则）
```

- `shared/core.js` 是唯一的「后端」：数据模型、演示数据、权限（public / member / applicant / admin）和全部 56 个接口。服务器和浏览器跑的是同一份代码，所以两种模式的行为完全一致。
- 前端没有框架：一个状态对象、一组 `html```` 模板函数（插值默认转义）、事件委托。
- 会员端的 Service Worker：页面与脚本「网络优先、离线用缓存」，字体图片「缓存优先」，接口从不缓存（会员端自己保存最近看到的数据）。

主要数据：`members` 会员 · `applications` 入会申请（含被推荐人与历史）· `events` / `rsvps` 节目与报名 · `reservations` 座位预订 · `books` 藏书 · `visits` 到访 · `requests` 按铃请求 · `bulletins` 公告 · `notices` 个人通知 · `floors` 楼层状态 · `staff` 员工 · `activity` 动态。

## 演示版和正式版的距离

- [ ] 真实短信验证码（阿里云 / 腾讯云短信），登录频率限制
- [ ] 员工账号、角色与权限（店长 / 会员服务 / 图书管理员），操作留痕
- [ ] 数据库（目前是一个 JSON 文件）与备份
- [ ] 入场码：demo 用的是可演示的哈希算法；正式版用 TOTP（服务端保存密钥），前台用扫码枪或摄像头扫二维码
- [ ] 推送：iOS 16.4 起，添加到主屏幕的 Web App 支持推送；国内安卓浏览器的 Web Push 不可靠，重要通知要走短信或服务号模板消息
- [ ] 隐私政策与个人信息授权（《个人信息保护法》），申请资料的保存期限
- [ ] HTTPS 与 ICP 备案（同官网）
- [ ] 后台「演示：当前入场码」辅助功能要去掉（接口 `admin.democode`）

## 和小程序的关系

先用 Web App 把流程、页面和设计跑通、给会员用起来；小程序以后作为另一个前端接入同一套接口即可。业务规则都在 `shared/core.js`，接口形状（`POST /api/<method>`）对小程序的 `wx.request` 同样适用，届时只需要补微信登录（`code2Session`）和手机号授权。
